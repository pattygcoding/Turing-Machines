# Assembly (64-bit) Implementation

Win64 NASM calling `ReadFile`/`WriteFile` directly, with no C runtime.

One of 42 implementations of the same console protocol in the
[Turing Machines](../../README.md) repository: every implementation reads
the same stdin and prints **byte-for-byte identical output**, so a single
master test verifies them all at once.

* **Category:** Systems
* **Source:** [`langs/Assembly/64bit/TuringMachine.asm`](TuringMachine.asm)
* **File-extension tag:** `.asm`
* **Showcase route:** [https://turing.pattygcoding.com/assembly64](https://turing.pattygcoding.com/assembly64)

## Prerequisites

* **Toolchain:** NASM plus a MinGW-w64 (x86-64) linker
* **Check it is installed:** `nasm -v`

| Platform | Install command |
| --- | --- |
| Windows | `choco install nasm mingw` |
| macOS | `brew install nasm` |
| Debian/Ubuntu | `apt-get install nasm gcc-mingw-w64-x86-64` |

## How to run

From the repository root, build this implementation and replay every
scenario:

```sh
python tests/run_tests.py --only assembly64
```

Build and run it on its own:

```sh
nasm -f win64 -o tests/build/turing_machine_asm64.obj langs/Assembly/64bit/TuringMachine.asm
gcc -o tests/build/turing_machine_asm64 tests/build/turing_machine_asm64.obj
./tests/build/turing_machine_asm64
```

## Protocol

[`README.md`](../../README.md#the-machine-and-the-console-protocol)
documents the machine and the exact output, and
[`tests/run_tests.py`](../../tests/run_tests.py) holds the build and run
commands the suite uses for every language.
[`tests/expected/`](../../tests/expected) is the authoritative golden output.

The nine scenarios cover a plain increment (`1011`), `0`, `1`, a full carry
chain (`1111` -> `10000`), a leading zero (`00101` -> `00110`), an empty
tape, a long tape (`0101010101` -> `0101010110`), rejected invalid input and
end of input.

## Notes

* The tape and output buffers are fixed-size, and the whole two-line result is assembled in memory and written with one `WriteFile` call.
